v2.72.2 · fake op that logs its calls

Today: every command signs in

status, diff and apply each ran op signin --raw, then op read. That's the same pair that failed on work WSL with authorization timeout.

Work: read once, then never

init made 2 calls, then status, diff and apply made 0. The saved config file was -rw-------.

Changed secrets need a refresh

A plain re-init kept the old value. DOTFILES_REFRESH_SECRETS=1 chezmoi init read it again and the next apply wrote the new one.

Service mode: no sign-in

With the token set, chezmoi ran only op read. Without it: onepassword.mode is service, but OP_SERVICE_ACCOUNT_TOKEN is not set.

The mode and token must match

Token set while still in account mode: onepassword.mode is account, but OP_SERVICE_ACCOUNT_TOKEN is set. Change both together.

Modelled, not tested

1Password's docs: an approval lasts 10 minutes idle (12 hours at most), and Windows sub-shells each need their own. Over SSH, nobody sees the popup. The page assumes the Mac reuses an approval in one terminal and Windows and WSL ask every time.
